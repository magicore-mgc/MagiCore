# `mgc-exec::run`

This module owns process execution and stable public entry points. `run/mod.rs` is the export/declaration facade and `run/run.rs` owns orchestration and policy flow; `types/` owns public request/report shapes and nearest tests; `environment/` owns guarded PATH composition, deny-shim temporary paths and local environment types/errors; `project_binary/` owns capture and inherited-stdio execution for explicit project/package binary paths; `process_isolation/` configures platform-specific pre-spawn isolation and owns the monitored-inspector capability check; `spawn/` owns the one shared child-process pipeline; `supervision/` owns waiting, cancellation, and pipe draining; `timeout/` owns timeout selection and environment parsing with typed errors; `shutdown/` owns the process-wide stop flag and OS handler registration, surfacing registration failures before spawn with native causes; `termination/` owns Unix process-group signal planning, local typed scan/probe/signal errors, and the bounded TERM/KILL sweep; `output/` owns byte-bounded output conversion and tail formatting; `runtime_invocation/` owns runtime-specific argv entrypoint parsing (Node, Python, PHP, shell, Dart, and Windows cmd); `rustc_child/` owns constrained Rust compiler-child recognition and trusted-parent checks; `process_scan/` owns Linux `/proc`, macOS BSD snapshots, and Windows scan types, PID identity/ancestry/command classification, bounded retry and native process snapshots; `windows_job/` owns Windows Job Object handles, membership/policy inspection, root-exit lifecycle and deferred cleanup errors; `dependency_policy/` owns ecosystem-specific dependency-resolution rules for Cargo/Rustc, Go, Python, .NET, Flutter/Dart, Swift, Gradle/Maven and Zig; `validation/` validates project-bound path arguments and owns local typed errors. Each behavior owner keeps exports/declarations in `mod.rs`, its implementation in `<owner>.rs`, focused tests under `test/`, and a README that documents the folder contract. Child modules must preserve `mgc_exec::run::*` exports and keep OS-specific code behind explicit platform owners.

`mgc-exec::run` sở hữu luồng thực thi process và các entry point ổn định. `run/mod.rs` chỉ export/khai báo và `run/run.rs` sở hữu orchestration/policy; `types/` sở hữu cấu trúc request/report public và test gần module; `environment/` sở hữu ghép PATH có bảo vệ, deny-shim tạm, cùng type/error riêng của môi trường; `project_binary/` sở hữu chạy capture và inherited stdio cho đường dẫn binary project/package tường minh; `process_isolation/` cấu hình cô lập trước spawn theo OS và sở hữu kiểm tra native inspector cho chế độ monitor; `spawn/` sở hữu pipeline process con dùng chung duy nhất; `supervision/` sở hữu vòng chờ, cancel và drain pipe; `timeout/` sở hữu phân giải timeout, kiểm tra biến môi trường có lỗi typed và test lân cận; `shutdown/` sở hữu cờ dừng toàn process, đăng ký handler theo OS và trả lỗi kèm nguyên nhân native trước spawn; `termination/` sở hữu kế hoạch signal process group Unix, lỗi scan/probe/signal typed cục bộ và lượt TERM/KILL có giới hạn; `output/` sở hữu chuyển đổi output có giới hạn byte và định dạng tail; `runtime_invocation/` sở hữu parse entrypoint argv theo runtime (Node, Python, PHP, shell, Dart và Windows cmd); `rustc_child/` sở hữu nhận diện compiler child Rust theo argv giới hạn và kiểm tra parent tin cậy; `process_scan/` sở hữu snapshot Linux `/proc`, macOS BSD và type, identity/ancestry/command PID, retry có giới hạn cùng native snapshot của Windows; `windows_job/` sở hữu handle Windows Job Object, kiểm tra membership/policy, lifecycle root-exit và lỗi deferred cleanup; `dependency_policy/` sở hữu quy tắc chặn tải dependency theo từng hệ Cargo/Rustc, Go, Python, .NET, Flutter/Dart, Swift, Gradle/Maven và Zig; `validation/` xác thực đường dẫn theo ranh giới dự án và sở hữu lỗi typed cục bộ. Mỗi owner để export/khai báo trong `mod.rs`, implementation trong `<tên-owner>.rs`, test chức năng ở `test/` và README ghi rõ hợp đồng folder; các module vẫn bảo toàn export `mgc_exec::run::*` và tách code theo OS rõ ràng.

The `invocation_policy/` owner contains exact-manifest exceptions, MGC self-answered probes, compat-runner recognition, and the ordered pre-spawn policy gate. Its compatibility-facing functions remain re-exported through `run/mod.rs` for the parallel runner.

Owner `invocation_policy/` chứa exception manifest chính xác, probe MGC tự trả lời, nhận diện compat-runner và chuỗi policy trước spawn. Các hàm tương thích vẫn được export qua `run/mod.rs` cho parallel runner.

The `audit_entry/` owner maps executor reports to audit records and enforces argv redaction at that boundary; serialization and file writes remain in the crate-level audit module.

Owner `audit_entry/` ánh xạ report executor sang audit record và thực thi redact argv tại ranh giới này; serialize và ghi file vẫn do module audit cấp crate đảm nhiệm.

The private `ProcessMonitor` carries the root `ExecutionScope` through Unix descendant scans and Windows Job inspection. Existing DeviceControl-only `adb`/`xcrun` policy now applies to matching children as well as direct project binaries; this is a narrow process-tree policy, not network isolation or a general sandbox.

`ProcessMonitor` nội bộ mang `ExecutionScope` của root qua scanner descendant Unix và Windows Job. Rule DeviceControl hiện có cho `adb`/`xcrun` giờ áp dụng cho process con match cùng với binary project trực tiếp; đây chỉ là policy hẹp trên cây process, không phải cô lập mạng hay sandbox tổng quát.
