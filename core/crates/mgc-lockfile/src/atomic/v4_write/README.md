# v4 write / Ghi v4

This owner refuses ordinary rewrites when the document carries a signature and publishes verified bytes through create-new staging, no-follow on Unix, file sync, atomic replacement, and Unix directory sync. Failed attempts retain the prior cleanup behavior.

Owner này từ chối rewrite thông thường khi document có chữ ký và publish byte đã xác minh qua staging create-new, chống follow trên Unix, sync file, thay atomic và sync directory trên Unix. Thất bại giữ nguyên cách cleanup hiện tại.

The public functions keep the existing `LockfileResult` contract and map local source-carrying errors back to `SignedLockMutation` or `WriteFailed` with unchanged display text.

Các hàm công khai giữ contract `LockfileResult`, ánh xạ lỗi cục bộ còn source về `SignedLockMutation` hoặc `WriteFailed` với thông báo không đổi.
