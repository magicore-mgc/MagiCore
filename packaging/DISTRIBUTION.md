# Distribution Contract

This file summarizes the current release contract. For install instructions and signing requirements, see [`README.md`](README.md). For the executable pipeline, see [`.github/workflows/release.yml`](../.github/workflows/release.yml).

## Release assets

The release contains two variants across these five target tuples:

| OS | Architecture | Archive |
|---|---|---|
| Linux | x64 | `.tar.gz` |
| Linux | arm64 | `.tar.gz` |
| macOS | x64 | `.tar.gz` |
| macOS | arm64 | `.tar.gz` |
| Windows | x64 | `.zip` |

Variants are `magicore` and `magicore-web`, for ten archives total. Every archive has a `.sha256` sidecar and a CycloneDX SBOM. Windows ARM64 is not currently published.

Names are generated by `scripts/release/release-artifact-contract.sh`:

```text
magicore-<version>-<os>-<arch>.<tar.gz|zip>
magicore-web-<version>-<os>-<arch>.<tar.gz|zip>
```

## Integrity and publication gates

- `scripts/release/release-manifest.py --require-matrix` requires every archive in the ten-asset matrix.
- SHA-256 files are checked against archive bytes before publication.
- Homebrew/Scoop manifests are finalized from those archives; source placeholders must never be published.
- The release manifest is signed with the Ed25519 key supplied as the GitHub Actions secret `MGC_RELEASE_SIGNING_KEY`; publication fails if the key is missing.
- The tag workflow creates a draft release. A maintainer publishes it only after the draft's checks pass.

The installer script verifies the SHA-256 sidecar. Clients verifying the signed release manifest must also pin the matching public trust root; the signing seed is never distributed.

## Local versus release builds

`bash scripts/release/release.sh --profile release` builds the nine `mgc-dist` package variants for the current host under `dist/`. It is a local binary build, not the cross-platform release matrix. The GitHub release workflow builds the two published variants for all five release targets and packages the archives.
